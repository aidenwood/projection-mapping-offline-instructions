Stage Technician's Field Manual · Volume II

NDI Bridge — Mac TouchDesigner ↔ Windows Resolume

Sending visuals one way or both ways between a Mac running TouchDesigner and a Windows machine running Resolume Arena, over a single Ethernet cable, with no internet, with low enough latency that you can keystone visuals on the Mac and still trigger them from the Windows side.

Section 01

Why NDI, not Syphon

Three protocols, only one of them crosses operating systems.

There are three common ways to pass video frames between apps in live visuals:

ProtocolWhere it livesCross-machine?Cross-platform?
SyphonMac, between apps on the same MacNoNo (Mac only)
SpoutWindows, between apps on the same Windows machineNoNo (Windows only)
NDIAnywhere on the same networkYesYes (Mac, Windows, Linux)

Syphon and Spout move frames through shared GPU memory on a single machine — extremely low latency, zero network overhead, but locked to one OS and one box. NDI moves frames over Ethernet — slightly more latency, real network cost, but it doesn't care which side runs what.

For sending visuals between your Mac and your Windows machine, NDI is the only option that works natively. There are paid bridges (Spout-to-NDI, Syphon-to-NDI) but they're just NDI under the hood. Skip them.

Same machine still uses native protocols

If you ever want to pipe TouchDesigner to another Mac app (or Resolume to another Windows app), use Syphon or Spout respectively — they're faster than NDI on a single machine. NDI is for the cross-machine link.

Section 02

Core concepts

Five minutes of theory before you start clicking.

Sender and receiver

NDI is a two-side protocol. A sender announces itself on the network and pushes frames out. A receiver discovers senders and pulls their frames in. Any app can be a sender, a receiver, or both at the same time on different streams.

Discovery

NDI uses mDNS (Bonjour) for automatic discovery — senders advertise themselves, receivers see them appear in a list without any manual IP configuration. This works beautifully when both machines are on the same subnet, and not at all when they aren't. The "is NDI discovery working" question is really "is mDNS working on this network."

Bandwidth

NDI's default mode is high-quality (around 100–150 Mbit/sec for 1080p60). Run it on gigabit Ethernet. NDI HX is a lower-bandwidth variant (around 8–20 Mbit/sec) intended for Wi-Fi and remote work — you don't need it for a wired stage setup.

Latency

Expect 1–3 frames of latency end-to-end on a clean wired link. At 60 fps that's 17–50 ms, fine for visuals. It's enough that you'd notice if NDI were in a camera-to-monitor loop for a presenter, but for music-driven visuals it's invisible.

NDI Tools

NewTek (now part of Vizrt) ships a free suite called NDI Tools for both Mac and Windows. The essentials in there are:

  • NDI Studio Monitor — a viewer that shows any NDI source on the network. The fastest way to verify a stream exists before involving any creative software.
  • NDI Test Patterns — generates a known-good NDI source. Use this to isolate "is the network working" from "is TouchDesigner working."
  • NDI Access Manager — lets you scope discovery to specific groups so dozens of NDI sources don't pollute a venue's network. Usually unnecessary for a single-show setup.

Install NDI Tools on both machines before you leave the studio. Caveman simple: if Studio Monitor on Windows can see a Test Pattern from the Mac, your network is fine and any creative-software issue is in the creative software.

Section 03

Network setup

Same subnet, wired, Wi-Fi off, nothing fancy.

  1. Direct cable, or both on a switch. The two reliable topologies are: Mac and Windows both plugged into the same gigabit switch (recommended, frees a port for the DMX node), or one Cat6 cable directly between the two machines (works fine if the rest of the rig doesn't need the network). Avoid Wi-Fi entirely.

  2. Set static IPs on both Ethernet interfaces. Pick a small private subnet that doesn't conflict with anything else in the rig. A common choice: Windows on 10.0.0.10, Mac on 10.0.0.11, DMX node on 10.0.0.20, all with subnet mask 255.255.255.0 and no gateway.

    On macOS: System Settings → Network → Ethernet → Details → TCP/IP → Configure IPv4: Manually.

    On Windows: Settings → Network → Ethernet → Edit IP assignment → Manual → IPv4 on.

  3. Disable Wi-Fi on both machines. This is the single biggest cause of NDI discovery failing. macOS and Windows both have a habit of treating Wi-Fi as the "default" network interface, so NDI announces and listens on Wi-Fi while your actual data is going over Ethernet. Disable Wi-Fi entirely or, on macOS, drag Ethernet above Wi-Fi in Network → Service Order.

  4. Disable any VPNs, firewalls, or "antivirus network shields." They block mDNS and NDI's discovery ports. macOS firewall: System Settings → Network → Firewall → Off (or allow incoming for TouchDesigner and NDI Tools specifically). Windows Defender firewall: same drill — turn off for the private network profile, or whitelist Resolume and NDI Tools.

  5. Test the network with ping. From Mac terminal: ping 10.0.0.10. From Windows command prompt: ping 10.0.0.11. Both should reply. If either doesn't, fix the network before opening any creative software — you'll just chase ghost bugs otherwise.

  6. Verify NDI discovery with NDI Tools. On the Mac, open NDI Test Patterns and let it run. On Windows, open NDI Studio Monitor — the Mac's test pattern source should appear in the right-click source list within 5 seconds. If it does, your network is healthy. If not, see the troubleshooting section.

NDI Access Manager groups

If you've ever set non-default NDI groups in Access Manager and forgotten about it, sources won't appear across machines whose groups don't match. Open NDI Access Manager on both machines and confirm both are sending and receiving on the same group (default is just public).

Section 04

Mac: TouchDesigner sending NDI

Putting your generative content onto the network.

TouchDesigner has built-in NDI output. There are two ways to expose a stream:

Method A — Touch Out TOP

The simplest way. Drop a TouchOut TOP on your network, set its Output Type parameter to NDI, connect the TOP you want to send into its input. Give the stream a clear name in the Name parameter (e.g. TD_Main) — this is what shows up on the Windows side.

Method B — NDI Out TOP

TouchDesigner also has a dedicated NDI Out TOP. Functionally identical to TouchOut TOP in NDI mode for most purposes; some builds give you a few extra options like alpha channel control. Pick whichever your version of TD has.

  1. Open your TouchDesigner project. Find or build the chain of TOPs that produces your final composited content. Whatever feeds your local preview is what should feed the NDI sender.

  2. Drop a Touch Out TOP at the end of that chain. Wire your final TOP into its input. The TOP itself doesn't render anywhere visible on the Mac — it's just the network exit point.

  3. Set Output Type to NDI. The TOP's parameter window has an Output Type dropdown. Pick NDI.

  4. Name the stream sensibly. Set Name to something descriptive like TD_PBR or TD_Particles. NDI streams are advertised as MachineName (StreamName), e.g. STUDIO-MAC (TD_PBR). Avoid spaces and punctuation.

  5. Set the output resolution. Match it to what Resolume expects on the receiving side — usually your composition resolution. 1080p is a safe default. 4K will work on gigabit but eats bandwidth and CPU.

  6. Verify on the Mac side first. Open NDI Studio Monitor on the Mac itself, right-click, find (your machine name) → TD_PBR, click it. If you see your output here, the sender is healthy.

  7. Now check on Windows. Open NDI Studio Monitor on Windows. The Mac source should appear in the right-click list. If it does, the link is alive end-to-end.

Multiple streams from one Mac

You can have several Touch Out TOPs in the same project, each with a different name. Resolume will see each one as a separate NDI source and you can place them on different layers. Useful if you want a PBR overlay on one layer and a particle layer on another.

Section 05

Windows: Resolume receiving NDI

Pulling the Mac's stream into the composition as a layer.

Resolume Arena treats NDI sources like any other clip. They live in the Sources panel under the NDI category. Drag them onto a layer like a video file.

  1. Confirm NDI is enabled in Resolume preferences. Preferences → Sources → NDI. There's a toggle. It should be on by default; confirm it is.

  2. Open the Sources panel. Bottom-left of the Resolume UI by default, alongside Files, Effects, etc. Click Sources, then expand the NDI section. Any NDI sources on the network should be listed here, named by machine (stream).

  3. Drag the Mac's NDI source onto an empty clip slot. Resolume creates a clip that plays the stream live. You can drag this clip to any layer like any other clip. Hit the clip to make it live, and you should see the Mac's output appear in your composition preview.

  4. Set the clip's transform to match your needs. The NDI feed comes in at whatever resolution the Mac sent. If your composition is 1920×1080 and the Mac sends 1920×1080, no scaling is needed. If they differ, use the clip's transform parameters or a Transform effect to fit.

  5. Layer-blend the NDI stream over your existing composition. Put the NDI clip on a layer above your projection-mapped content, set the blend mode (Add, Screen, Overlay) to taste, and dial the opacity. This is how you get the PBR overlay sitting on top of your base visuals — the next manual covers the specifics of what to put inside the NDI stream.

NDI source disappears mid-show

If the Mac's stream drops, the clip slot in Resolume shows black. Add a fallback clip on a lower layer or set the layer's autofade to kick in if the NDI source disconnects. Don't trust NDI alone for a hero moment — always have a baked video fallback for the same beat.

Section 06

Windows: Resolume sending NDI back to the Mac

Closing the loop so the Mac can react to what Resolume is rendering.

If you want the Mac to know what Resolume is currently rendering — say, so TouchDesigner can render a PBR overlay that responds to the base composition's brightness, or so you can keystone the final mapped output from TD — you need Resolume to send NDI in the other direction.

  1. Enable Resolume's NDI output. Output → NDI from the menu bar. Resolume immediately starts broadcasting the master composition as an NDI source named after the Windows machine and "Resolume Arena" or similar.

  2. Verify on Windows first. Open NDI Studio Monitor on Windows itself and confirm the local stream appears. If it does, Resolume is broadcasting correctly.

  3. Verify on the Mac. Open NDI Studio Monitor on the Mac, right-click, find the Windows machine's Resolume stream. You should see live video.

  4. Receive into TouchDesigner. Drop an NDI In TOP on your TD network. In its Source Name dropdown, pick the Resolume stream from the list. Wire the TOP into wherever you want it — a feedback chain, a colour analysis network, a keystone op.

Per-layer vs master NDI

Resolume's main Output → NDI sends the final master composition. If you want only one layer's output, you can place a Direct Output on a layer and route it to NDI individually. Useful if you want to send a pre-FX clean feed back to the Mac for analysis.

Section 07

Mac: TouchDesigner receiving NDI

Reading any NDI source into TD as a TOP.

  1. Drop an NDI In TOP on the network. Single op, no input wires needed.

  2. Click the Source Name parameter dropdown. TD will list every NDI source it can see on the network. Pick the Windows/Resolume stream.

  3. Set the resolution mode. The default is to inherit from the source — leave it there unless you have a specific reason to resample. Resampling on the TOP adds a frame of latency.

  4. Wire it into your TD network as input to whatever you want to do with it. Common uses: feedback effects that react to Resolume's output, colour sampling for matching PBR lighting to the composition's palette, geometry-projection effects that use Resolume's content as a texture on a 3D scene.

Section 08

Keystone from TouchDesigner

Using TD as the final mapping surface, with Resolume feeding it.

You mentioned you can keystone from TouchDesigner easily — if you want TD to be the projection-mapping surface rather than Resolume's Advanced Output, the flow is:

Inverted topology: TD does the mapping
   [Resolume Arena] ──NDI──→ [TouchDesigner: NDI In TOP]
   (Windows)                       │
                                   │ wired into a Render TOP
                                   │ with a textured plane
                                   ↓
                            [Cornerpin TOP / SOP keystone]
                                   │
                                   ↓
                          [TouchOut TOP → projector HDMI]
                          (Mac drives the projector)

This swaps which machine owns the projector. The Mac plugs into the projector via HDMI, runs full-screen TouchDesigner output, and reads its content from Resolume over NDI. Reasons to do this: TD's cornerpin and 3D-projection operators are more flexible than Resolume's Advanced Output for unusual surfaces; you can apply per-corner softening, mesh-based warping, or full 3D camera-projection mapping using the live NDI stream as the texture.

  1. Decide which machine owns the projector. If TD is going to handle keystone, the projector plugs into the Mac. Resolume still runs on Windows but only outputs to NDI — it doesn't drive a physical display.

  2. In Resolume, disable Advanced Output if you don't need it locally. Send the master composition out NDI as in Section 06. Resolume's job is now "be a media server feeding TD."

  3. In TD, receive Resolume's NDI into a Cornerpin TOP or Camera Projection setup. A simple cornerpin: NDI In TOP → Cornerpin TOP. Drag the four output corners to align with your surface. For complex 3D mapping, use a Geometry COMP with the NDI feed as the material texture, then render the camera view.

  4. Output the warped result to the projector. Send TD's final TOP to a Window COMP set to perform mode on the projector display. Dialogs → Window Placement or right-click the Window COMP. Set to perform mode, full screen, on the projector's display index.

  5. Verify the round-trip. Trigger a clip in Resolume — it should appear on the projector via TD, with TD's keystone applied. Latency is two NDI hops if you also send TD back to Resolume for any reason; one NDI hop if it's a one-way flow.

Hybrid: keep both mapping surfaces alive

You don't have to pick one. Resolume can map most of the stage via Advanced Output (driving its own HDMI to projector A) while TD maps a separate sculpture or surface via NDI (driving its HDMI to projector B). For a two-projector show that needs different mapping qualities, this is the way.

Section 09

Performance & latency

What to expect, what to tune if it's not enough.

Bandwidth budget

One 1080p60 NDI stream burns roughly 125 Mbit/sec. Two simultaneous streams in opposite directions on a gigabit switch is still comfortably within the 1000 Mbit budget. Four streams will start to stress a cheap switch; eight will need a managed gigabit switch with proper buffering.

CPU cost

NDI encoding and decoding both run on CPU. On both Mac and Windows, expect 10–20% CPU usage per 1080p60 stream. If you're seeing higher than that, check whether the source resolution is higher than you think (NDI doesn't auto-downscale).

Frame rate matching

Run sender and receiver at the same frame rate. If TD is rendering at 60 fps and Resolume's composition is at 30 fps, Resolume drops every other NDI frame. Match composition and TD project framerate before showtime.

Reducing latency

  • Use a dedicated gigabit switch with no other traffic on it.
  • Disable any "energy efficient Ethernet" power-saving features on both NICs — they introduce variable latency.
  • Disable Windows' GPU scheduling toggle if you're on an older driver — it can add 1–2 frames of input latency to NDI-receive.
  • If you don't need alpha, don't send alpha — fewer bytes per frame.
Section 10

Troubleshooting

When the green link light is on but nothing shows up.

NDI source from the Mac doesn't appear on Windows at all

This is almost always one of three things, in order of likelihood:

(1) Wi-Fi is still on. NDI is announcing on Wi-Fi (or expecting to hear announcements there) instead of Ethernet. Turn Wi-Fi off entirely on both machines.

(2) Firewall blocking mDNS. macOS firewall blocks incoming on TouchDesigner. Windows Defender blocks Resolume. Turn off the firewall for the private network profile, or explicitly allow the apps.

(3) Different subnets. Ping each from the other. If ping fails, fix IPs before doing anything else.

Stream appears but is black, or shows last frame frozen

The sender registered itself but isn't actually producing frames. On TouchDesigner: confirm the input to your Touch Out TOP is actually rendering — wire a Constant TOP into it as a test, you should see solid colour. On Resolume: confirm the master composition has content. Frozen-last-frame usually means the sender stopped rendering but didn't disconnect the stream.

Stream flickers, tears, or shows blocky compression

Bandwidth issue. Either: the switch is overloaded (try a direct cable), the cable is bad (swap it for a tested one), or you're on a 100 Mbit link not gigabit (check the link speed in network settings on both machines). Cat5e is fine for gigabit; Cat5 (without the e) is not.

NDI works, then drops after a few minutes

Two common causes: (1) a thermal-throttled NIC dropping connection — let the machines warm up before the show and check none of them are running hot in a confined road case. (2) Network sleep/power-saving — disable energy-efficient Ethernet and "allow this device to be turned off to save power" on Windows NICs.

Latency is too high — visuals lag behind clip triggers

Expect 1–3 frames. If you're seeing more than that, check: framerate mismatch between sender and receiver (the bigger gap will be visible as judder, not pure latency), NDI HX mode accidentally enabled somewhere (it adds buffering), Resolume's Preferences → Sources → Buffer Frames set high (lower it to 1).

Multiple NDI sources confuse the receiver

If you have several test streams running from old sessions, they'll all advertise on the network. Quit anything you don't need. Worst case, open NDI Access Manager and put your show machines in a custom group so unrelated sources are filtered out.

Section 11

Pre-show checklist

Tick before you trust the bridge.

  • NDI Tools installed on both Mac and Windows.
  • Static IPs set on both Ethernet interfaces; subnets match.
  • Wi-Fi disabled on both machines.
  • Firewalls disabled or apps whitelisted on both machines.
  • Ping succeeds in both directions.
  • NDI Studio Monitor on Windows sees a test pattern from the Mac.
  • NDI Studio Monitor on Mac sees Resolume's NDI output from Windows.
  • TouchOut TOP in TD named clearly; resolution matches Resolume's composition.
  • Resolume's NDI Source panel shows the Mac stream and it plays as a clip.
  • Composition framerate matches TD project framerate.
  • Backup baked video file ready on Resolume in case NDI drops.
  • Switch link lights all solid; cables physically secured/taped.
Section 12

Glossary

Bonjour / mDNS
Multicast DNS, Apple's zero-configuration service-discovery protocol. NDI uses it to find sources on the network. Implemented natively on macOS; Windows machines need Bonjour Print Services or the bundled NDI Tools installer for it to work reliably.
NDI
Network Device Interface. NewTek/Vizrt's protocol for sending uncompressed-quality video over Ethernet. Cross-platform.
NDI HX
A lower-bandwidth, slightly higher-latency NDI variant intended for Wi-Fi and remote workflows. Avoid for stage use.
Spout
Windows-only protocol for passing video between apps on the same machine via shared GPU memory.
Syphon
Mac-only equivalent of Spout. Doesn't cross machines.
TOP
Texture Operator. TouchDesigner's 2D image-processing operator family. NDI In TOP and Touch Out TOP are the two endpoints.
